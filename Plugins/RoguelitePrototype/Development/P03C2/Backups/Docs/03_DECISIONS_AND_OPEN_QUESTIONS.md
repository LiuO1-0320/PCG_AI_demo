本文供 Codex 识别决策权重，**不能因早期聊天或举例数值而私自更改已确定规则**。

更新：2026-10-12，DOC-UPDATE-01。本文记录未来开发约束，不改写 P00–P03-A 的既有验收。旧规则的替代关系见 E；待测试数值见 C，尚未决策事项见 D。

## A. 明确确定（Locked v2.1）

- 引擎 Unreal 5.8.3；Codex + **Epic 官方 Unreal MCP**；Nwiro 不再是主工具；用户不手写代码。
- 4 人、6 周、单人 PC、每局约 20–30 分钟、无跨局继承或退出续玩。
- 参数化矩形房间外壳自由调整长宽高，手工 POI/内墙/凹槽不自动变形；门洞默认居中且可手动偏移。
- 新游戏在 `Plugins/RoguelitePrototype/` 和 `Content/Roguelite/` 独立开发，不依赖 CastleDemo 玩家/AI/房间生成/PCG/Boss；保留现有项目及全局默认设置。
- 正式地牢所有允许玩家通行的房间连接都须包含**参数化走廊**，长/宽/高独立可编辑；首版水平直线，未来 L 型、弯曲及特殊连接模块。水平直角旋转和已有 Door Socket 保留；随机主线必到 Boss，允许多分支；未使用门洞封堵。
- P03-A Direct 不删除，保留底层能力和测试用途，**不再作为正式地牢默认通行连接**。逻辑连接记录 Room、Socket、模式、有效状态，空间实现按模式处理；不得把直接贴墙条件推广到走廊模式。
- **Fog Transition Corridor** 替代单层 Fog Gate：从已清理房间到下一房间经过浓雾走廊，自由移动和观察，逐渐遮挡前后信息、接近出口渐进揭示。首版优先低成本局部可配置表现，不要求复杂实时体积雾。
- 下一房外壳、手工 POI、PCG 掩体/敌军候选点、全部普通敌军及必要导航，在正式 Preparation 前准备完毕；迷雾只能提供视觉缓冲，须有未就绪安全等待/遮挡，不依赖固定穿行秒数。雾不代替游戏逻辑、实体碰撞或攻击检测。
- 混合式 PCG 掩体：手工区域指定开阔区/密集区/POI/通道保护区，PCG 生成低/高/组合掩体。
- 普通敌军 PCG 出生点：散布 + 小群组混合；避开玩家本次入口、安全边界、手工结构、掩体；PCG 提供点位和属性，C++ 负责生成敌人。
- 玩家经走廊正式进入未清理战斗房，确保存活且可行动队友安全入房，随后封锁入口，再进入**无限时 Preparation**。敌军已一次性预生成且继续休眠；玩家可自由走近敌军，队友 Follow/Defend 但不主动射击。不能把队友关在走廊。
- 玩家第一枪**命中当前 Preparation 房间 Enemy**才进入 Combat，立即逻辑封锁**所有有效连接门**，所有普通敌军激活，之后不能恢复 Preparation；首次远程 EQS 在激活后。清除全部有效敌军后 Cleared，解除所有合法连接门封锁；重访已清理房不重复首次战斗流程。
- 初次 Enemy 目标为最近有效 Alive Friendly（玩家 + 招募队友），保持锁定直到死/倒地/失效/持续不可达；单纯丢失 LOS 不换目标。
- 慢速近战 BT、不救援；远程 BT+EQS，近距站定有 LOS 才射击，远距找合法射击位置，有限弹匣、无限备用弹药、自动换弹。
- 只有远程感染者能在倒地后解救成为队友，阵营转换不新造一套敌人；初始编队容量 2，局内可扩容，后期最大约 10 人是目标。
- Follow/Defend，跨房间自动取消 Defend 恢复 Follow；进入战斗房并封入口前安全集结；跟随编队 + RVO + 防守点预约；必要时玩家/友军选择性穿行。
- Friendly 互相不伤害，Friendly 的子弹能够穿过 Friendly，但不穿墙；Enemy 子弹可以正常伤害 Friendly。
- Friendly 倒地后有救援窗口；清关可继续救；玩家**正式进入下一房间**才遗弃上一房未救 Downed、本局永久阵亡。仅进入连接走廊不触发遗弃；自然救援期限仍有效。
- 商人简单交互；Boss 另组员负责，仅接口集成。
- 关卡策划能分别调整房间物资、敌人掉落、清关奖励与其权重/数量，重要奖励在 Cleared 后解锁。
- 后续允许**只读审查并评估**旧 CastleDemo 的种子随机纯拓扑逻辑；是否迁移复用须另行记录结论，不能直接依赖旧房间生成、AI、PCG 或 Boss。最终地牢由随机逻辑图、参数化房间、Door Socket 和参数化走廊共同构成。

## B. 已采用的技术实现优先级（可按实测替换）

- 独立插件 C++ 组装房间/走廊和管理状态；UE 原生 Actor/组件；PCG Graph 管理各类生成数据。复用范围优先 Roguelite 已验证实现及引擎原生能力，不自动复用旧 CastleDemo 游戏类。
- 三个 PCG Graph：Cover、EnemySpawn、RoomProps；课程展示 3 项独立 PCG 技术，不只数 Graph。
- 基础 AI 使用 Character + BT/EQS，AI 目标检索事件触发，EQS 节流；先不用 Mass/Detour Crowd。
- **真实的 UE API / MCP 操作范围是运行时探测结果，不属于设计已确认事实。**
- `DA_RoomDefinition` / `DA_RoomLootProfile` / `DA_EncounterProfile` 等是建议名称，优先复用工程现有资产。

## D. 尚未正式决定（Codex 不得擅自永久拍板）

1. 远程感染敌人的**解救交互时长与倒地持续时间**：与 Friendly 35s/2s 分离。建议等待玩家离开本房/不设计时，但需要用户确认。
2. 队伍已满时远程感染者的解救操作：建议不占位不能招募，但倒地仍算清怪；空位出现后仍可招募未移除目标，需用户确认。
3. 游戏内物品与武器的具体物品 ID、玩家是否也采用无限弹药、敌人掉落触发点/经济权重：等待系统需求。
4. Boss 的房间战斗触发、分阶段刷新及事件合同：需 Boss 负责人确认。
5. 快捷键（救援 E 的初测除外）、UI 样式、取消/警告交互行为：待玩法测试。
6. PCG 密度参数、房间尺寸、门洞宽度、最小净距、NavMesh Agent 配置：首个灰盒垂直切片后决定。
7. 关卡类型默认配置和特殊模板覆盖的具体字段优先级：由 Roguelite 物品/掉落需求决定，不自动依赖旧 CastleDemo。
8. 水平走廊长宽高默认/最小值、门洞尺寸适配规则、连接器引用/路径字段、必要 NavMesh Agent：在基础走廊灰盒中实测；未来完整模板 POI 刚性装配不因本次文档而实现。
9. 低成本局部雾的具体技术、距离/曲线/性能预算，以及玩家停留、折返时的表现：待体验与性能测试。
10. 未就绪等待区域、准入阻挡/攻击隔离、超时与失败反馈/恢复；不能只使用计时或雾材质替代功能。
11. 正式入房的精确边界与幂等事件、队友集结成功标准和失败恢复、遗弃 UI；必须满足 A 中的顺序，不把走廊进入当正式入房。
12. 旧纯拓扑算法的可复用性及解耦成本：后续只读评估，本轮未审查/迁移，也未继承旧地图房型与数量规则。
13. **P03-C1 已由用户正式批准，取代 DOC-UPDATE-01 时任务正文缺失的记录。** 范围见 `../prompts/P01_TO_P13_TASKS.md`：只开发独立直走廊 Actor、可编辑尺寸/厚度、两个 P02 兼容端点及隔离测试图。P03-A 人工验收已确认，不补记未验证导航；不加入 Fog Transition、准备同步、战斗门控、自动 Room→Corridor→Room 拼接、随机地牢或 AI。实施/验收结果以执行状态与本轮报告为准，不凭批准记为通过。
